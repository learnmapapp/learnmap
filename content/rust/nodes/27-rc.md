---
title: Rc and RefCell
icon: "🔗"
branch: memory
requires: [box, borrowing]
summary: Shared ownership, and mutation checked at runtime.
---
Ownership says one owner per value. But sometimes data really is shared: two nodes in a graph pointing at the same child, or several widgets holding the same settings.

`Rc<T>` (reference counted) allows several owners. Cloning an `Rc` doesn't copy the data, it bumps a counter. The value is freed when the last `Rc` is dropped:

```rust
use std::rc::Rc;

let settings = Rc::new(String::from("dark mode"));
let a = Rc::clone(&settings);
let b = Rc::clone(&settings);
println!("{}", Rc::strong_count(&settings)); // 3
```

An `Rc` only gives out shared (`&`) access, because several owners changing the same thing is exactly what Rust protects you from.

When you need to change it anyway, add `RefCell<T>`. It moves the borrowing rules from compile time to **runtime**:

```rust
use std::cell::RefCell;

let log = Rc::new(RefCell::new(Vec::new()));
let writer = Rc::clone(&log);

writer.borrow_mut().push("started");
println!("{:?}", log.borrow()); // ["started"]
```

Same rules as always (many readers *or* one writer), but break them and you get a panic instead of a compile error:

```repl shell
> cargo run
thread 'main' panicked: already borrowed: BorrowMutError
```

```tip
`Rc<RefCell<T>>` is the "I really need shared mutable state" escape hatch for single-threaded code. Across threads, the same idea is `Arc<Mutex<T>>`, see [Shared state](node:arc-mutex).
```

```quiz
question: "What does `Rc::clone(&x)` do?"
options:
  - Makes a deep copy of the data.
  - Increments a counter and returns another pointer to the same data.
  - Moves the data out of x.
answer: 1
explain: That's why Rust style is to write `Rc::clone(&x)` instead of `x.clone()`, to make it
  obvious it's cheap.
```
