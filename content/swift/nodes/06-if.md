Swift's `if` is almost what you'd expect, minus some punctuation:

```swift
let temperature = 31

if temperature > 30 {
    print("Hot! 🥵")
} else if temperature < 5 {
    print("Bring a coat 🧥")
} else {
    print("Lovely 😎")
}
```

Notice two things:

1. **No parentheses** around the condition. You may write them, but nobody does.
2. **Braces are mandatory**, even for a single line. This doesn't compile: `if ok print("yes")`. That rules out the famous bug where someone adds a second line to an unbraced `if` and it runs every time.

Since Swift 5.9, `if` can also be an **expression** that produces a value. That's great for keeping a `let` without a dance of reassignments:

```swift title=shipping.swift
let total = 42.0
let shipping = if total >= 50 { 0.0 } else { 4.95 }
print("Shipping: \(shipping)")
```

When `if` is used this way, each branch must be a single expression of the same type, and an `else` is required. Otherwise, what would `shipping` be?

Swift also still has the classic ternary operator `? :`, which is handy for very short choices inside a larger expression:

```swift
print("You have \(count) item\(count == 1 ? "" : "s")")
```

Use whichever reads better. A good rule: ternary for tiny inline choices, `if` expressions for anything you'd want to read twice.

```compare python
shipping = 0.0 if total >= 50 else 4.95
```

```compare kotlin
val shipping = if (total >= 50) 0.0 else 4.95
```

```compare rust
let shipping = if total >= 50.0 { 0.0 } else { 4.95 };
```

```exercise
goal: Turn the var-and-reassign pattern into a single let with an if expression.

  var ticket = "adult"
  if age < 12 {
      ticket = "child"
  }

  - notMatch: 'var\s+ticket'
    message: ticket should become a let.
  - match: 'let\s+ticket\s*=\s*if\s+age\s*<\s*12\s*\{\s*"child"\s*\}\s*else\s*\{\s*"adult"\s*\}'
    message: 'Write: let ticket = if age < 12 { "child" } else { "adult" }'
solution: |-
  let ticket = if age < 12 { "child" } else { "adult" }
```
